# 0.2.8：片库回顶与转场减负

- 双击底栏“片库”平滑回到顶部；首次单击切页立即响应。慢点、拖动和取消不识别为双击，回顶不清空搜索或筛选，也不重新创建片库页。系统减少动态效果时直接回顶。
- 详情采用 Flutter 自带的横向不透明页面转场，取消详情整页透明混合，保留海报共享动画及普通直接访问。没有引入新动画组件依赖。
- 修正 Hero 目的页临时离屏测量被当成动画结束的问题。已有影片数据先呈现，入场完成后再刷新本地详情、读取观影记录；快速返回取消延后工作，编辑中的内容仍受保护。不额外请求豆瓣。
- 详情头部在展开/折叠状态之间切换时才更换静态组件树，不随每个滚动位置重建海报、文字和渐变。
- 海报卡片按压用独立缩放动画更新，重用海报和文字子树。片库预构建范围由 0.9 屏调整至 0.55 屏，继续使用分页和惰性网格。
- 详情背景、缩略海报、网格海报统一使用已有 300px 解码/磁盘缓存项，避免转场后另建 480px 背景缓存和突然替换占位背景。
- 不调整数据结构、已看规则、同步逻辑、代理、权限、依赖、包名和签名。

## 检查与发布

运行 flutter analyze --no-pub、flutter test --no-pub，构建 arm64 release。核对包名、版本、ABI、签名与 SHA-256；上传 v0.2.8-ui.1 APK、源码与校验清单，验证公开下载后再切换 update-ui.json。保留 update.json 旧渠道。

自动化回归包括真实嵌套路由下双击回顶、首次切页不延迟、慢点/拖动不误触、减少动态效果、保留页面状态、海报往返与快速返回、本地加载及编辑保护、卡片子树复用、详情头部滚动复用、千部片库惰性构建、小屏大字体。

发布后使用与手机相同的更新/下载服务检查 0.2.7 发现 0.2.8、实际下载进度与摘要匹配、0.2.8 不重复提示。此联网测试在电脑执行，不代替 Android 安装器验收。

## 小米澎湃 OS 4 验收

1. 从 0.2.7 设置内检查并下载更新，覆盖安装，不先卸载。
2. 片库下滑数屏，双击底栏“片库”：回到标题和搜索框，搜索/筛选条件不变。连续重复并检查慢点和横拖不误触。
3. 快速上下滑动海报网格，点影片、返回，再立即打开另一部；注意入场/返回、海报和背景是否连贯。
4. 详情滚到底再返回，确认片库保留原位置；更改短评后返回，确认未保存提醒与草稿保护仍正常。
5. 浅深色、系统返回、减少动态效果和键盘收起分别体验。

本轮没有连接手机进行性能采样，不宣称固定帧率或完全消除卡顿。自动化可以验证工作是否延后、组件是否复用及交互正确；实际掉帧改善仍以手机体验/后续采样为准。
