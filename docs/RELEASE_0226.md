# 片刻·焕新版 0.2.26

## 修复：删除过的影片无法重新添加

**现象**：添加某部影片时报错
`保存失败: DatabaseException(UNIQUE constraint failed: movies.id ...)`。

**根因**：`movies.id` 是数据库主键，而删除是**软删除**——
只是把 `deleted_at` 打上时间戳，数据行仍然留在表里，主键继续被占用。

但两处查重都带着 `deleted_at IS NULL` 条件：

- `getMovieById()`
- `_getMovieByDoubanSubjectId()`

它们把墓碑行当作「不存在」，于是查重全部通过，
真正 `INSERT` 时被数据库主键拦下。

所以只要一部影片被删过，就永远无法再添加回来。

**修复**：插入前先查同 id 的墓碑行，命中则**复活**它——
用新内容覆盖整行并清掉 `deleted_at`，而不是插入新行。
既满足「删了还能重新添加」的预期，也不产生重复主键。

## 修复：导出诊断日志显示为空

**现象**：遇到错误后点「导出诊断日志」，提示「暂无可导出的错误记录」。

**根因**：0.2.23 加的错误边界只接管 `FlutterError.onError` 与
`PlatformDispatcher.onError`，这两个只捕获**没人接的**异常。

但本项目大量错误是这样处理的：

```dart
} catch (error) {
  _error = '保存失败: $error';   // 显示在界面上，在 Dart 看来已处理完毕
}
```

这类失败全局处理器收不到，可它恰恰是用户真正遇到的问题
（比如上面那个主键冲突）。这是上一版的设计缺陷。

**修复**：

- `AppErrorLog` 新增 `recordHandled(scope, error, stack, detail)`，
  供业务层在 catch 里显式上报。
- 已接入添加影片、更新影片、删除影片、批量添加四条主路径，
  记录时附带 id / 标题等上下文。
- 批量添加原先用 `catch (_) {}` 完全吞掉异常，
  用户只看到「有 N 部失败」却不知原因，现在也会记录。

## 新增回归测试

5 项测试覆盖软删除后重新添加的各种情形，并已验证：
**回退修复后这些测试会报出与用户截图完全相同的错误**，
确认测试确实能捕获该缺陷。
