# 片刻·焕新版 0.2.36

## 新增：电视剧分集也能进观影日历

### 之前的问题

电影在详情页点「记录观影」会写一条带日期的记录，日历能读到。
但电视剧是**逐集勾选**的，原来分集只有一个「看过没有」的开关，**没有日期**：

```dart
class MovieEpisode {
  final bool watched;   // 只有开关，没有时间
}
```

所以你花 5 天看完一部 12 集的剧，日历上这 5 天**全是空白**，
只有另外手动点「记录观影」才会补上一天。两条数据是割裂的。

### 现在的做法

**给每一集记录一个日期。**

- 勾选第 5 集 → 第 5 集记下「今天」
- 取消勾选 → 日期一并清空
- 补勾（比如一次勾到第 8 集）→ 新勾上的都记为今天，
  **已看过的保留原日期**，不会被改成今天

**日历同时读两个来源**：观影记录（电影）+ 分集日期（电视剧）。

你 11/10 到 11/14 每天勾几集，日历上这 5 天就都会出现这部剧的封面。

### 某天看了几集也能看到

点击日历中某一天，弹层里每部剧下面会显示：

- `第 5-7 集` —— 连续集号自动压缩成区间
- `第 5、7、9 集` —— 不连续用顿号分隔
- `第 5 集` —— 单集不带连字符

电影仍然显示时间（`20:30`），因为电影没有分集。

## 三条约定

**① 老数据不补假日期**

升级前已经勾过的分集没有日期，它们**不会**进入日历，也不会被补成「今天」。
只有从这个版本起新勾的分集才有日期。已经过去的那些天仍然是空的，
但不会再产生新的空白。

**② 取消勾选能回退**

勾错了取消勾选，日期一起清掉，日历上那一天也会相应消失。
如果当天所有集都取消了，这一天该剧就从日历里消失。

**③ 不伪造历史**

没有任何「批量把老数据刷成今天」的逻辑。

## 技术细节

- `MovieEpisode` 新增 `watchedAt` 字段，存 ISO 字符串
- 老 JSON 没有这个字段时解析为 `null`（向后兼容，不报错）
- 没有日期时**不写出**该字段，保持旧备份的 JSON 形状
- `copyWith` 增加 `clearWatchedAt` 开关 —— 只传 `null` 无法区分
  「不修改」和「清空」
- 日历查询**不在 SQL 里解析 JSON**：Android 7 的系统 SQLite 未必编译了
  JSON1 扩展（现有代码的「全部看完」判定也是因此用 `LIKE`）。
  改成 SQL 只做月份粗筛，日期解析放在 Dart 层，跨版本安全且可单测
- 不改数据库版本号，不改备份 schema，不需要迁移
