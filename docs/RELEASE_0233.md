# 片刻·焕新版 0.2.33

## 修复：备份包含已删除的影片

**现象**：片库显示 94 部，但「上传备份」的确认框说 116 部。

**根因**：删除是**软删除**——只给 `deleted_at` 打时间戳，数据行还留在表里。
而导出备份时直接 `txn.query(table)`，**没有过滤 `deleted_at IS NULL`**：

```dart
final movieRows = await txn.query(_moviesTable, orderBy: 'created_at ASC');
```

片库查询走的是视图 `v_movie_state`，那里带了过滤，所以显示 94；
备份直接读表，所以拿到 116。两边都「正确」，只是看的不是同一批数据。

### 实际影响比数字对不上更严重

1. **已删除的条目会被同步到别的设备**。上传后再在另一台设备恢复，
   那些你以为删掉的影片会重新出现。
2. **导入时会让墓碑数据「复活」**。`_replaceAllInTxn` 是先全删再插入，
   而插入时 `_stamp` 写的是 `deleted_at: null`——备份里带的墓碑行
   到了新库就变成正常影片。
3. 备份文件体积虚增。

## 修复

`readBackupBundle` 给所有带 `deleted_at` 列的表补上 `deleted_at IS NULL`：

- `movies` / `viewing_sessions` / `collections` / `collection_members` / `tags`
- `movie_tags`：除自身墓碑外，再排除指向已删除影片或标签的孤儿关联

**注意 `draw_records` 不加这个条件**——该表没有 `deleted_at` 列
（抽片记录不做软删除）。加错会让查询直接报错，已通过测试验证。

## 新增测试

`test/services/backup_excludes_deleted_test.dart` 6 项：

1. 删除影片后，备份里的影片数与片库计数一致
2. 删除观影会话后，备份里的会话数同步减少
3. 删除标签后，关联表里的孤儿行也被排除
4. 抽片记录不受影响（该表没有 `deleted_at`，不能被条件误伤）
5. 全部删除后备份为空，不报错
6. **备份 → 导入往返后，已删除的条目不会复活**（守住上面第 2 条影响）

## 你现有的云端备份

云端那份 116 部的旧备份**仍然是脏的**。本版只保证新上传的备份干净。

处理方法：装上本版后，在设置里点「上传备份」覆盖一次云端即可。
覆盖后确认框会显示与片库一致的数字。
