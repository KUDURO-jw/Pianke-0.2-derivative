# 片刻·焕新版 0.2.34

## 修复：连续删除多部时提示条叠加

**现象**：短时间内删多部影片，底部会叠出多条撤销提示，导致卡顿和闪屏。

**根因**：撤销提示条没有做单例。每调一次 `deleteWithUndo` 就
`overlay.insert` 一条新 entry，删三部就叠三层，每层各跑自己的倒计时
与弹簧动画，画面持续重绘。三层叠在一起，用户也分不清「撤销」
点的是哪一部。

**修复**：全局只保留一条提示。新提示出现时，旧提示立刻关闭
（按「被顶掉」处理 → **确认删除前一部**），新提示接管位置。

关键点：被顶掉的那一部仍然会 `commit`。如果只是简单丢弃，
它既从界面消失、又没写进数据库，重启后会「复活」——
测试里专门守住了这一条。

## 修复：删除后补位没有动画

**现象**：删掉一部影片，后面的卡片直接跳到新位置，很生硬。

**根因（两层）**：

1. 网格用的是 `SliverGrid.builder`，它根本没有「移除动画」的概念。
2. 更关键的：我上一版把它换成 `SliverAnimatedGrid` 后**仍然没效果**——
   这个组件只在**显式调用 `removeItem(index, builder)`** 时才播
   移除与补位动画。数据一变就重建，行为与普通网格完全一样。

**修复**：

- 网格改用 `SliverAnimatedGrid`，并持有 `GlobalKey` 以取得 State。
- 删除流程里先算被删项在当前列表的下标，调 `removeItem` 播退场动画
  （卡片缩小 + 淡出，高度收拢），**再**更新数据。顺序很重要：
  先改数据会让索引错位，拿不到正确的动画起点。
- 恢复时对应调 `insertItem`，让卡片滑回原位。
- 遵守「移除动画」开关：该设置打开时直接移除，不做过渡。

## 新增测试

- `test/ui/undo_singleton_test.dart` 3 项：连续删除只留一条提示、
  被顶掉的提示仍会提交删除、单条时正常超时。
- `test/ui/grid_reflow_test.dart` 2 项：`removeItem` 后出现
  `SizeTransition`（证明补位动画接上了）；未调用时没有动画载体（对照）。

第二条对照测试很有价值——它记录的正是我上一版犯的错：
**换了组件不等于接上了动画**。
