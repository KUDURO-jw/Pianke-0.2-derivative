# 焕新版更新发布

焕新版包名 app.pianke.personal，独立读取 main/update-ui.json。旧版读取 update.json，不修改该文件。

用户在设置中手动检查；使用 versionCode 比较，清单缺少该字段时才比较 versionName。0.2.6 起显示应用内下载进度并在校验后打开 Android 安装确认；0.2.5 及更早版本通过外部浏览器下载。不做启动检查、后台轮询或静默安装。

后续版本发布步骤：
本项目用户所说的「推送」包括源码推送与应用内更新发布。仅推送 Git 提交不能视为交付完成；需验证线上更新清单和公开 APK，再报告发布成功。连接失败时使用电脑现有代理重试，并核对远程提交确实更新，不以本地提交代替推送成功。

1. 提高 pubspec.yaml 的版本和构建编号，保持包名及签名不变。
2. 完成分析、测试、Release arm64 构建和签名验证。
3. 发布 GitHub Release，提供 APK、该版本源码、SHA256SUMS.txt；确认公开下载地址有效。
4. 最后更新并推送 main/update-ui.json 的版本号、更新说明、APK 地址及 APK 的 sha256；forceUpdate 默认 false。

## 0.2.5（10）：排版、转场与流畅度

- 片库缩小标题留白，无自建合集时显示紧凑入口；有自建合集时保留手动/智能合集横条并降低高度。海报尺寸、筛选、分页和添加入口不变。
- 剧集分集成为独立卡片，放在观影记录之前；保留连续标记与保存失败回退规则。
- 外观改成一行三选，移除设置入口重复说明；同步状态和操作常驻，已配置账号默认收起配置，未配置时展开。恢复覆盖、冲突选择、凭据安全存储不变。
- 二级页面统一 280ms 进入、220ms 返回；系统减少动态效果下时间为零。四个主页仍约 300ms，动画更新不再重新创建 Navigator 子树。
- 底栏用 Flutter SpringSimulation 独立实现吸附，拖动直接跟手；移出逐帧更新范围的玻璃、裁剪和阴影不再反复构建。保留有界甩动，合并跨项及松手的重复触觉反馈，取消手势恢复原项。
- 片库、合集及抽片结果的海报使用独立来源标识进入详情；不带角标和标题。详情首帧接收可选本地影片快照；继续读取本地最新数据，已开始编辑时不覆盖输入。缺图、直接链接和减少动画有普通转场兜底。图片缓存和 300px 缩略图解码复用，不为转场补取豆瓣信息。
- 数据库、Provider、服务、抽片算法、备份格式、旧 update.json 和依赖锁文件不变；无新增权限或依赖。
- 小屏大字体下分集标题、观影记录日期及操作自然换行；顶部缩略海报随详情滚动消失后，返回使用普通页面转场。

### 小米手机验收

本次按用户的小米手机、澎湃 OS 4 使用场景检查布局与系统避让，未接入真机，不代表已验证该机型的实际帧率。无需修改系统设置或刷新率。

1. 覆盖安装后检查片库和观影记录仍在；片库快速上下滚动，确认吸顶筛选可点、底栏和添加按钮不挡住最后一行。
2. 连续切换四个主页，再返回原页，确认滚动位置保留；慢拖底栏、短距离快甩、按住后取消，确认跟手且不会一下冲到两端。
3. 从片库、合集和抽片结果点击海报进入详情，用系统返回手势或返回按钮退出；快速来回也不应闪屏或错位。
4. 打开剧集，确认分集在观影记录之前，点选分集保存后退出再进检查进度。
5. 详情滚到底部，确认顶部没有异常色块；输入短评后收起键盘，检查页面位置和可见操作。
6. 设置切换主题、展开/收起同步配置，确认已输入配置保留，恢复和冲突确认仍正常。

若出现卡顿，反馈手机具体型号、发生步骤、是否首次进入和屏幕录制；之后根据复现情况做真机定位，不把组件测试结果当作手机性能结论。

## 0.2.6（11）：应用内下载更新

- 原先“下载新版”只将 URL 交给外部应用，无法获知浏览器是否真的开始下载。现改为应用内显示百分比和已下载/总大小；无 Content-Length 时显示已下载大小。
- 支持取消、失败重试，区分超时、无法连接和服务器拒绝；下载及校验期间系统返回先取消下载。只在用户点击后下载，不增加启动检查、后台轮询或后台下载服务，不修改代理或豆瓣请求规则。
- APK 流式写入应用私有缓存，不读写公共目录、不请求存储权限；取消和失败清理临时文件，成功后只保留最新校验通过的更新包。重新打开弹窗可复用同版本、同摘要的已下载文件。清除缓存后需重新下载；进程被系统终止时不提供断点续传。
- 清单新增 sha256，应用在下载后流式校验；错误页面、空文件、截断或摘要不符不能进入安装。未提供有效摘要的旧清单仍可检查，但不允许直接下载。另有限制防止异常大文件占满缓存。
- 点击“安装新版”才调用 Android。原生侧在工作线程验证缓存路径、APK 包名、目标版本及现有签名；通过 FileProvider 临时只读授权给系统安装器。新增 REQUEST_INSTALL_PACKAGES 权限；Android 8+ 首次可能打开“允许此来源”设置，允许后需返回再次点击安装。不会静默安装或自动确认。
- 沿用现有包名、证书及全部 0.2.5 改动，无新增依赖。仍需代理覆盖片刻应用及 GitHub/资源域名，开着代理但未覆盖本应用时仍可能下载失败；软件不能代替代理转发。
- 0.2.5 及更早安装包无法自行获得新的下载界面，首次需手动覆盖安装 0.2.6，之后遇到新版才使用应用内下载。
- 验证：静态检查零问题；完整自动化测试 100 项通过，涵盖流式进度、未知大小、缓存复用、取消和清理、失败重试、异常文件拦截、小屏大字体、系统返回取消、安装权限结果及既有业务回归。另外显式使用电脑本机代理，通过实际下载 0.2.5 的 GitHub Release APK 验证重定向、进度及 SHA-256；未接入手机，不代表已验证澎湃 OS 的 VPN 分流和安装确认。电脑直连测试未走通，随后改用电脑现有代理验证，未改变手机或应用代理配置。

手机验收：检查更新 → 下载新版 → 核对进度与大小 → 取消并重试 → 下载校验完成 → 点击安装 → 允许此来源（若提示）→ 返回再次点安装 → Android 确认。同版本不提示更新是正常结果。电脑测试不能替代小米澎湃 OS 4 的实际下载、代理分流和安装权限验收。
