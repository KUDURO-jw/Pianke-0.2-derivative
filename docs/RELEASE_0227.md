# 片刻·焕新版 0.2.27

## 改进：抓取遇到限流自动退避重试

**现象**：刚进入应用添加影片时报错，过几秒再试就正常了。

**原因**：豆瓣的限流是**短窗口**——刚进应用或连续几次请求后会被拦，
几秒后自动恢复。原来代码只在详情页做了单次重试，搜索路径完全没有，
用户只能自己反复点。

**改进**：新增统一的退避重试，搜索与详情都走它。

- 遇到 403 / 429 时，先清掉可能失效的挑战凭证
- 退避等待 1 秒、2 秒，最多尝试 3 次
- 非限流错误（如 500、404）不重试，立即抛出，不浪费用户时间
- 总等待上限约 3 秒，比让用户手动重试再失败一次体验更好

## 说明

- 新增 4 项退避测试，覆盖：403 重试后成功、连续 403 超限抛出、
  非限流错误不重试、首次成功不产生额外请求。
- 退避时长按项目规则放入设计令牌 `Motion.scraperRetryBase`，
  业务代码不出现裸的 `Duration` 字面量。
- 验证：静态分析零问题；业务测试 203 项（新增 4 项）、
  前端测试 135 项、视觉基线 6 项全部通过；动效令牌检查通过。

本版递增为 0.2.27（33），沿用 `app.pianke.personal` 与既有发布证书，
可从 0.2.26（32）直接覆盖更新，无需卸载。

### 验证边界

退避逻辑在测试中用脚本化的 HTTP 替身验证（可精确控制第几次返回 403），
真机上豆瓣的实际限流窗口长度需安装后确认。
